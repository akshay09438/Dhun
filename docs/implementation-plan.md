# Prompt-DJ — Implementation Plan

_How far along we are, what's in flight, what's left, and the drift log. Living document — updated at each milestone and at `/zuko:handoff`._

## Status: **M1–M3 complete; M4 complete in code — Slice A live-confirmed, Slices B+C built — 106 tests passing (96 backend + 10 web).** M4 = the full arrangement (vocal weaves in/out, beat-breath), Regenerate, the arrangement screen (Slice A, live-confirmed) + contrast (both songs trade vocals), one subtle filter sweep, and confidence fallbacks (Slice B, built + reviewed SAFE) + the **energy-arc fix** (Slice C: vocal spreads across the WHOLE song with a strong finish, not clustered in the middle — verified end-to-end on the real 7:52 pair). Next: live listen on the full M4 (arc + contrast + sweep), then M5 (live commands) — with the mix-cache eviction sweep to land before the ~50-user test.

Demand is founder-validated, so we skipped the hand-made validation gate (former "M0"); the first real proof point is **M3** — the first genuinely good mix.

**M2 was split into M2a (stem separation) and M2b (analysis), stems first.** The heavy audio-AI runs in the cloud (Replicate), because PyTorch cannot run on the founder's Windows-ARM machine (proven — see [cloud-and-cost-plan.md](cloud-and-cost-plan.md)).

## Deltas from the original PRD (decided during discovery, 2026-07-05)

- One target user (casual creators), not three.
- Feature 2 leaner + Regenerate promoted to first-class.
- Short-clip (15–30s) export added as a hero output.
- Live BPM change explicitly deferred to V2.
- Right-sized stack: SQLite + local storage + in-process jobs for validation (audio toolchain unchanged).
- Time-stretch: SoundTouch (free) by choice, swappable to Rubber Band.

## Curated demo pairs (to assemble before/with M3)

~10 pairs: mostly _compatible_ (close BPM, Camelot-adjacent, clear structure) to showcase quality; 2–3 _hard_ pairs to exercise fallbacks. Hand-verify grid/key/sections. Include a couple of Indian pairs, hand-checked (weaker analysis there).

Verified live on Father Ocean: POST returns in 1s, ready after ~90s. This matches the PRD's original async-jobs intent, deferred in M1/M2a and now needed.
- 2026-07-06 — **M3 built (the first real mix).** The brain plans, the engine executes (LLM never touches audio). New pieces: the **fence** (`app/planner/fence.py`) computes legal, safe options from both analyses (phrase-aligned high-energy drops, safe tempo stretch with octave-folding, vocal slice, key fit); the **AI driver** (`app/planner/plan.py`) has Claude pick among them with a deterministic fallback so a mix never blocks on the AI; the **referee** (`app/planner/validate.py`) checks the plan (R3 on-beat, B3 safe stretch) and the finished audio (R6 no clip / not silent); the **engine** (`workers/render.py`) sums S1 drums+bass+other, atempo-stretches + places S2's vocal slice with click-free fades, optional one-bar beat-breath, peak-normalizes to −1 dBFS. Async route (`app/routes/mix.py`, mirrors stems/analysis) caches the WAV by content hash of (song1, song2, prompt). Web: a **Make my mix** card → poll → play + download + DJ-language note. `MixPlan`/`Mix` models added. 35 backend + 2 web tests added (70 total); real-render end-to-end passes through FFmpeg on synthetic songs.
- 2026-07-06 — **Drift resolutions (M3):** (1) **Time-stretch = FFmpeg `atempo`, not SoundTouch.** Same class of tool (pitch-preserved tempo change), already installed, no extra binary to ship, and license-clean (LGPL core) for a commercial build — the local dev FFmpeg _does_ carry GPL `librubberband`, but the pipeline deliberately does **not** depend on it. Stretches kept within ±8% (fence declines wider pairs). SoundTouch/Rubber Band remain swappable if a demo pair ever needs a heavy stretch. (2) Added the `anthropic` SDK to the API venv (pure-Python, ARM-fine) for the driver. (3) `workers/render.py` lives at the repo root (matching the danger-glob) and is imported by the API via a small `sys.path` bootstrap in the mix route; it takes plain file paths so it stays decoupled from the app/db. Risk scorer rated both dangerous files `auto-apply` (low): new, additive, pre-launch; created via the confirm-and-apply flow with founder approval and an independent adversarial + scalability review before merge.
- 2026-07-06 — **M3 follow-ups (deliberately deferred):** the web flow still needs the two songs analyzed + split manually (per-card buttons) before "Make my mix" — the one-click "Studying your songs" screen (functional-spec Screen 2, auto analyze+split then mix) is a small UI task queued next. - 2026-07-06 — **M3 live-listen fix (first real mix on a compatible pair).** Founder heard a real merge — milestone hit — and reported a ~2-second silent "pause" right before the vocal enters. Root cause: the AI set `beat_breath=True` ("punchy re-entry"), and the engine renders that as one full bar of **dead-air silence** before the vocal (~2s at 122 BPM) — which reads as the song pausing, and also makes the beat's re-entry feel off. Fix: the M3 planner now forces `beat_breath` **off** so Song 1's beat plays continuously under the vocal (honours the "music never stops" invariant); `ENGINE_VERSION` bumped `m3.1→m3.2` so cached gappy mixes aren't re-served. The engine's beat-breath capability stays (for M4) but is no longer triggered in M3. **M4 backlog:** rework beat-breath as a real tension move (bass-cut / filter / build, not silence); add drift/phase-lock across long placements (Handbook 9.6) — some vocal-vs-beat drift over a long single placement is a known M3 limitation. (Expected-not-a-bug, confirmed with founder: the vocal enters once on the loudest section, so the first stretch is untouched instrumental — the full weave is M4.)
- 2026-07-06 — **Independent reviews (scalability + adversarial safety) on M3.** Scalability verdict: ship at validation scale; architecture clean and right-sized. Two items applied immediately: a cache-version tag (`ENGINE_VERSION` folded into `mix_id`) so tweaking the engine/prompt never serves a stale cached mix; and logging swallowed render failures (`log.exception`) so a systematic bug isn't invisible. Adversarial safety verdict: could not breach data, corrupt a mix, or serve a broken render through the real flow (one-vocal/one-bassline guaranteed by construction, id/path-injection closed, ready-ordering sound, clipping capped). Two "should-fix" gaps in the dangerous-surface guards — not reachable through today's fence but real — were **hardened with founder approval**: (1) `validate_render` now catches near-silence (≥2% audible), not just exact-zero, closing a hole in the very guardrail the profile calls the app's worst-failure defense; (2) `render.py` caps decoded audio at 12 min (byte cap ≠ duration cap → memory-DoS on a tiny-but-hours-long file) and adds defensive tempo/anchor guards. 4 tests added (65 backend, 74 total). Follow-up logged: add a **duration cap at upload** too (belongs with the pre-public hardening list). **Carried into the M4/scale backlog (do these deliberately, not by surprise):** (a) mix WAV cache has no eviction — the fastest-growing data, worse once M4 adds regenerate; add a "keep newest N"/age sweep or stop persisting the intermediate PCM_16 WAV. (b) When M4 adds multiple vocal placements, extend `MixPlan` **additively** (new optional `placements` list; the engine prefers it when present) — do **not** rename/repurpose `anchor`/`vocal_src`, because plans are cached to disk as JSON and old ones must still parse. (c) The async-job skeleton (`_HEX_ID` + in-memory `_jobs` + daemon-thread spawn + file-inferred readiness) is now in three routes (stems/analysis/mix) — extract a tiny `async_job` helper the next time the job model is touched. (d) In-memory `_jobs` + local-disk readiness are correct for single-worker validation but break at the first multi-worker deploy (duplicate renders, lost state) and on the move to object storage (exists() → network round-trip) — the persisted job table + storage seam the code comments already anticipate.

Fence gains `arrangement_options` + `vocal_slices`; the driver arranges 2–3 non-overlapping placements (Claude, with a deterministic fallback), `take` rotates them for Regenerate; the referee checks no-overlap across placements; the engine renders each placement and **ducks the bed to 35%** for the beat-breath (never silence — the M3 dead-air fix stands, and the M4-backlog "rework beat-breath as tension" item from 2026-07-06 is thereby **done**); the route threads `take` (`ENGINE_VERSION m4a.2`); the web mix screen shows a two-lane arrangement timeline + Regenerate + Download. 88 tests (78 backend + 10 web).
- 2026-07-06 — **M4 independent reviews.** Scalability: **ship**, additively extensible, no scale cliff at validation scale. Adversarial safety: **found a real must-fix** — FFmpeg `atempo=stretch` outputs `source/stretch` seconds, not `source*stretch`; the driver+referee used the inverted `*stretch`, so for `stretch<1` (a faster vocal, ~half of compatible pairs) vocals could **overlap (two voices)** past the checks, and the original tests asserted the same wrong formula. **Fixed with founder approval:** one shared `fence.placement_end` (source/stretch) used by both driver and referee; `_default_arrangement` fit corrected; AI slices re-clamped to `MAX_VOCAL_SECS`; real overlap tests at `stretch<1` added; `ENGINE_VERSION m4a.1→m4a.2`. Lesson: a green suite proves nothing if the tests encode the same bug as the code — the independent adversarial pass is what caught it.
- 2026-07-06 — **M4/Slice-B + scale backlog (logged, deliberate):** (a) **mix-WAV cache eviction is now the top item** — Regenerate multiplies write-once WAVs (~30 MB each); add a keep-newest-N / age sweep **before the ~50-user test** (deletes finished mixes → belongs in `storage.py`, a dangerous surface, so gate it). (b) render decodes the vocal once _per placement_ (≤3 ffmpeg calls, `_MAX_PLACEMENTS`-capped) — fine at this scale; decode-once-slice-in-memory is a note-for-later micro-opt. (c) beat-breath ducks stack multiplicatively (0.35×0.35≈0.12) if two breathing placements land within a bar — audible-not-silent, low severity, Slice-B polish. (d) deterministic fallback can start the vocal at `anchor=0` (no instrumental intro) — a Slice-B/UX nicety (kept out now to preserve Regenerate variety). (e) live-AI arrangement behaviour + prompt-injection via `user_request` unverified (all AI tests mock `_ai_arrange`); output is structurally clamped (anchors snapped, count capped, slices clamped) so blast radius is low. **Slice B** proper: keep-Song-1-vocal for contrast (add an optional `MixPlan.s1_vocal_regions`, do **not** overload `Placement.vocal_src`), FX (optional `Placement.fx`), richer per-element confidence fallbacks.
